## 今日のハイライト

### 1. [廃止] Targeted release が2027年1月に退役し、11月には割り当てを変更できなくなる — プレビューを先に受ける経路は Frontier だけになる

**要点**: Targeted release は2027年1月に退役する。11月以降は、管理者がユーザーを追加・削除・変更できなくなる。早期検証は Frontier の登録、GA の時期は Standard / Deferred release で管理する形に変わる。

**詳細**: Learn の一次 `targeted-release-retirement`（`ms.date` 10/7）は、TC の 10/26 記事が参照したことで本日はじめて検知した。
- 対象: M365 管理センター、Teams、OneDrive、SharePoint Online、Outlook on the web、新しい Outlook for Windows、Office for the web。Microsoft 365 Apps の更新チャネル、Windows の更新チャネル、Insider プログラムは対象外
- 退役後の扱い: 設定を変えないままの Targeted release ユーザーは、テナントの Standard / Deferred release の設定に従って機能を受け取る。Microsoft は「一部ユーザーだけ Targeted」の構成を「Deferred release にして、検証役のユーザーを Standard release に割り当てる」構成へ移すよう案内している
- 11月の変更: Frontier / Standard / Deferred をまとめて設定する「統合 Release Preferences」画面が M365 管理センターに入り、今の Standard / Deferred の設定画面は退役する
- GCC / GCC High / DoD: Deferred release と Frontier は提供されておらず、残るのは Standard release だけである
- 同日の TC 記事: 11月から Frontier の対象が新しい Outlook for Windows・OneDrive・SharePoint・Teams のパブリックプレビューへ広がる。Copilot 向けに Frontier へ登録済みのユーザーは、登録し直さなくてもこれらのプレビューを受け取るようになる。Frontier の登録に Copilot ライセンスは要らない
- https://learn.microsoft.com/en-us/microsoft-365/admin/manage/targeted-release-retirement
- https://techcommunity.microsoft.com/blog/microsoft365copilotblog/frontier-expands-to-more-microsoft-365-public-previews

### 2. [新機能+仕様] Cowork のモデルピッカーに Grok 4.7 が入った — 10/10 に告知された独立プロセッサ経路を、利用者が実際に選べるようになった

**要点**: Cowork の What's New に October 2026 節が加わり、Grok 4.7 と GPT 6.1 Sol（GPT 6 Sol の後継）がモデルピッカーに入った。Grok は xAI が独立プロセッサとして処理するため、選ぶと Microsoft の DPA の外で処理される。10/10 の時点では、モデル一覧に Grok は無かった。

**詳細**: `copilot/cowork/whats-new` は 10/24 01:03Z に `8d120c92`（`ms.date` 10/21）へ改訂されていた。
- Grok 4.7: 長文書・コーディング・多段タスク向け。`cowork-models` の表は「Provided by xAI as an independent processor」と書き、`connect-to-ai-models` へリンクしている。有効化には Global administrator が M365 管理センターの AI providers の設定を変える必要がある（10/10 既報）
- GPT 6.1 Sol: 「hard work」向けとして、GPT 6 Sol と置き換わった
- EU Data Boundary 内のテナントで使えるのは GPT 系だけである
- Projects: 関連するタスク・指示・文脈を1つにまとめる機能。プロジェクトは作成者本人だけのもので、プロジェクトの指示はグローバルの Cowork 指示より優先される。成果物（Outputs）からはファイルを削除できない
- https://learn.microsoft.com/en-us/copilot/cowork/whats-new
- https://learn.microsoft.com/en-us/copilot/cowork/cowork-models
- https://learn.microsoft.com/en-us/copilot/cowork/cowork-projects

### 3. [新機能] Power Platform 管理者が Cowork からテナントの統制状況を自然言語で問い合わせられるようになった — Power Platform Admin プラグインがプレビュー

**要点**: Cowork 向けの Power Platform Admin（preview）プラグインが公開された。管理者は、在庫・利用状況・所有者・DLP・容量・ライセンスを横断する質問を Cowork でできるようになる。これまで管理センターの複数の画面と PowerShell を組み合わせていた調査を、1つの会話にまとめられる。

**詳細**: プラグインは読み取り専用で、管理操作は実行しない。
- 展開: テナント管理者または Copilot 管理者が、M365 管理センター > Agents > Tools > Registry から対象ユーザーへインストールする
- 接続に必要なロール: Global Administrator / Power Platform Administrator / Dynamics 365 Administrator のいずれか。接続には Power Platform for Admins V2 コネクタの OAuth 接続を使う
- 注意: プラグインを入れても Cowork 自体の利用権は付かない。Cowork の利用権は、Cowork を含む支出ポリシーで別に与える
- 用途の例（ブログ）: 退職者が所有するアプリとフローの洗い出し、コネクタを止めたときに影響するアプリ・フロー・エージェントの特定、週次レビューの定期実行
- https://learn.microsoft.com/en-us/power-platform/admin/power-platform-admin-cowork
- https://techcommunity.microsoft.com/blog/copilot-studio-blog/introducing-the-power-platform-admin-plugin-in-cowork-agentic-governance-with-natural-language

  - https://www.microsoft.com/en-us/power-platform/blog/2026/10/26/custom-apis-just-landed-in-the-dataverse-mcp-server-agents-just-got-smarter/
