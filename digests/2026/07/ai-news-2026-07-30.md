# AI News Digest — 2026-07-30（木）

## 今日のハイライト

### 1. Copilot Studio の「エージェント提案」が本日 GA — 作るものを人が考える前に、利用ログ側から案が出てくる

**要点**: Copilot Studio で新規エージェントを作るとき、M365 Copilot のメモリと利用履歴から提案が最大3件出るようになった。

**詳細**: Release Wave の計画機能「Get Microsoft 365 Copilot agent suggestions based on your work in Copilot Studio」の GA 日が **2026-07-30**（本日）に設定されている。新規エージェント作成時に、そのユーザーの M365 Copilot メモリと過去の Copilot 利用状況を解析し、日常のタスクやワークフローに沿ったパーソナライズ提案を最大3件生成する。提案は Agent Builder 体験のテンプレート一覧に並び、「パーソナライズされた推奨」として既存テンプレートと区別して表示される。内容は現在の作業パターンに応じて定期的に更新され、新しい提案が出るとメール通知が発生する。ユーザーは公開前に提案されたエージェントを確認・修正でき、公開後は Copilot Studio で作った他のエージェントとまったく同じ挙動になる。前提条件として、対象環境で **M365 Copilot メモリ**が利用可能かつ有効になっている必要がある。なお一次ページ（`release-plan/2026wave1/microsoft-copilot-studio/` 配下）は本日 Learn MCP が M365 Roadmap の本文を返し、WebFetch も 403 だったため、本項の記載は二次ソースに依拠しており一次確認は未了である（末尾の改善メモ参照）。

**意味**: メモリを有効にしているテナントでは、エージェントの起案が「作りたい人が発想する」から「使用ログ側から提示される」方向に寄る。研修やハンズオンで受講者が「何を作るか」で止まる場面の入口が変わるため、演習シナリオを提案ドリブンに組み替える余地がある。逆にメモリ未有効のテナントでは提案が一切出ないので、当日の環境確認項目に入れておかないとハンズオンが空振りする。

### 2. Copilot Studio What's New の June 節に未掲載の4項目 — Foundry IQ の流用と Teams Phone 連携が実務に効く

**要点**: 6月節に、Azure AI Foundry のナレッジベース流用や Teams Phone 連携を含む4項目が載っていた。

**詳細**: 本日 Learn MCP で June 2026 節を全項目洗い直したところ、本ダイジェストで一度も扱っていない4項目を確認した。① **Foundry IQ 接続**（Preview）では、Azure AI Foundry で構築・チューニング済みのナレッジベースを、Copilot Studio 側で作り直さずエージェントの Microsoft IQ ソースとして参照できる。認証は API キー / クライアント証明書 / サービスプリンシパル / Entra ID 統合の4方式で、接続は1エージェントに1つまで。retrieval の結果が期待と違う場合は Copilot Studio ではなく Foundry 側でナレッジベースを調整する建付けになっている。② **Teams Phone Agent 連携**（Preview）では、Teams 管理センターでダイヤルキーの宛先に Copilot Studio の音声エージェントを割り当て、請求・処方箋補充・注文状況といった専用フローを担当させられる。ただし対象は basic voice agent のみ（real-time voice agent は非対応。音声タイプの変更は不可逆）、オーケストレーションは classic 必須（generative は 5〜6 秒の遅延が出るため非対応）、認証は「認証なし」必須、テナントは Microsoft サポート経由の個別有効化が必要で、環境側は「新機能を早期に取得」を「いいえ」にする。日本・France・Germany・India・South Africa は音声エージェント非対応リージョンで、Copilot Studio 環境は対応リージョンに作る必要がある。③ 新エージェント体験での他エージェント接続（Preview）では、フロントドア1つから専門エージェントへ委譲するモジュラー構成を組める。④ **条件グループ**では、Message / Question / prompt ノードの複数条件を1ノードに集約し、テーブル表示とグラフ表示を切り替えられる。既存の条件ノードの挙動は変わらず、コードエディターで条件グループ ID に `_tv` を付けるとテーブル表示に切り替わる。

**意味**: Foundry IQ は「検索とランキングのチューニングは Foundry 側の担当に寄せ、Copilot Studio 側は会話とツールに集中する」分担が取れる点で、AI 検索を別チームが持っている案件に噛み合う。Teams Phone 連携は制約が重く、提案段階で「音声は Copilot Studio で作れます」と言い切るとリージョンとオーケストレーションの要件確認で必ず戻るため、日本リージョン前提の案件では特に注意がいる。条件グループはトピックの見通しが良くなるので、研修教材のフロー例を書き換える候補になる。

## ガバナンス・管理

- **Purview DLP × Entra Global Secure Access**（Preview・7月）: 管理者が、ネットワーク層でテキストと AI 対話を傍受・検査し、DLP ポリシーに基づく制限アクションを適用できるようになる。ブラウザー・アプリ・API・アドインを経由した生成 AI プラットフォームや SNS への機密データ送信を抑止する用途で、Insider Risk Management 側でのリスク検知にも連動する。Purview の「What's new」7月節に Preview として掲載された。
  https://learn.microsoft.com/en-us/purview/dlp-network-data-security-learn
- **Cowork のモデル統制**: 管理者が、M365 admin center の Copilot 設定で Anthropic モデルファミリーを一括オフにでき、既定オフの **Claude Fable 5（Preview）**は明示的に有効化するまでモデルピッカーに出ない。Fable 5 はデータ保持が必要なモデルで、選択するとプロンプトと応答がモデルプロバイダー側に保持され、ピッカーの注記と選択中のバナーでその旨が表示される。Cowork の既定は no-retention なので、ここだけ扱いが異なる。
  https://learn.microsoft.com/microsoft-365/copilot/cowork/cowork-models
- **Cowork のブラウザー利用統制**: 管理者が、テナント設定 **Cowork Browsing** でブラウザー操作の可否を切り替えられる。ブラウザータスクはユーザー端末の Edge で動くため、既存の条件付きアクセス・DLP・閲覧ポリシー（allowlist / blocklist / 閲覧のみ）をそのまま継承し、Cowork が開始した各タスクは統合監査ログに記録される。課金は使用量ベースで、モデル応答・ツールとスキルの呼び出し・画像生成・ブラウザータスクがいずれも消費対象。
  https://learn.microsoft.com/microsoft-365/copilot/cowork/cowork-admin-governance
