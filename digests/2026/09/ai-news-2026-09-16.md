### 1. アプリ生成が環境ルーティングを全テナントで強制有効にする — 管理者が無効化できず、既存のルーティング構成があるテナントではメーカーがアプリを使えなくなりうる

**要点**: Cowork のアプリ生成は環境ルーティングを全テナントで自動的に有効にし、管理者はこの設定を変更できない。前提が「ルーティングは任意で入れる統制機能」から「アプリ生成を許した時点で入る既定」へ変わる。

**詳細**: `power-platform/admin/apps-default-environment-routing`（`ms.date` **2026-09-08**・`updated_at` 2026-09-08T19:04Z）が一次である。全 digest を grep して掲載歴ゼロを確認した。9/8 の MC1469329 と 9/10 の告知ブログはいずれも本リポジトリで掲載済みだが、どちらも本ページを参照していなかったため、告知を載せても統制の前提は載らない状態が8日続いていた。ページは冒頭で「この設定は変更できない」と明記している。

- ルーティング規則が無いテナント: *Everyone* をメーカー個人の開発者環境へ流す規則が1本自動作成され、Default Environment Group も同時に作られる
- ⚠️ 既存のルーティング規則があるテナント: 新しい規則は追加されない。ページは「これらのテナントでは一部のメーカーがアプリを使えないことがある」と書き、管理者が *Everyone* 向けの規則を自分で作るよう求めている
- 規則そのものの制約: *Everyone* を対象にする規則は削除できず、1本しか持てず、優先順位の最後に置く必要がある。*Everyone* がセキュリティグループより上にあるテナントは、以降の変更前に順序を直す必要がある。環境グループを選ばずに新規規則を作ることもできない
- ライセンス: アプリ用の個人開発者環境は既定でマネージド環境になる。そこで Power Apps / Power Automate のリソースを作らない限りプレミアムライセンスは不要で自動クレームの対象外だが、作る場合は該当するプレミアムライセンスが要り自動クレームの対象になる
- Dataverse: これらの環境に Dataverse は入っていない。PPAC から手動で追加するか、メーカーが Power Apps / Power Automate のメーカー画面でその環境を選ぶか流された時点で自動追加される

⚠️ ルーティングが有効になる範囲は他製品には広がらない。 アプリ単独でルーティングが入ったテナントのメーカーは、Power Apps / Power Automate のメーカー画面を開いても個人開発者環境へは流されず、既定環境や権限のある環境で作り続ける。他製品へ広げるかどうかは管理者が別途決める。

### 2. アプリ資産の管理面が Microsoft 365 管理センターに集約された — 棚卸し・コスト上限・作成経路の3つが管理者の当日の作業になる

**要点**: Copilot Studio と Cowork で作られたアプリの統制手順が公開された。棚卸し・クレジット上限・作成経路の選択がいずれも Microsoft 365 管理センターに集まる。前提が「新しい作成体験が来る」から「既存のアプリ資産管理と同じ運用に載せる」へ変わる。

**詳細**: Copilot Studio Blog に **2026-09-15 20:09Z** 付「Managing apps built in Copilot Studio」が公開された（掲載歴ゼロ・公開から11時間で検知）。記事は 9/10 の告知の続きにあたり、管理者が考えるべきことを「アプリ資産の棚卸し」「クレジット上限によるコスト統制」「作成経路の選択」の3つに整理している。アプリはメーカー個人の開発者環境に作られ、既存の環境ルーティングポリシーに従う。コネクタ権限とデータポリシーはビルド中も公開後も適用され、アプリはサインイン中の利用者の代理でデータへ接続するため、公開や共有によって本人が元々到達できないデータへの権限が増えることはない。

- 棚卸し: 公開済みアプリは管理センターに一覧化される。作成者・ライフサイクル状態・使用中のデータソースとコネクタ・適用ポリシー・利用状況と稼働メトリクスが並ぶ。同じ画面からアプリの停止と無効化、コネクタの削除、ポリシー逸脱の是正、共有可否の制御、退役ができる
- コスト: ビルドとランタイムは別々のサービスとして計量される。ビルド消費はモデル・アプリの複雑さ・反復回数で変わり、ランタイム消費は処理するタスクの量と複雑さで変わる。ランタイムは Power Apps Premium ライセンスがあれば既存のリクエスト上限内に収まり、上限を超えるかライセンスが無い場合に Copilot Credits で課金される
- 上限: 上限はメーカー用・ランタイム用ともユーザー単位で、従量課金の設定から管理する。全員に同じ予算を置くことも、部門ごとに分けることもできる。⚠️ 環境単位の上限は記事が「今後来る」と書いており現時点では無い
- 作成経路: 管理センターの Apps > Overview にある「Choose where people can make apps」で選ぶ。Copilot Studio 経路は既定で有効かつ推奨、Cowork 経路は組織の Frontier 参加状況で決まる。経路を切ると新規作成は止まるが、その経路で既に公開されたアプリは動き続ける

⚠️ プレビュー中は利用者が途中で遮断される。 Learn の `microsoft-365/admin/manage/apps/` は「クレジット要件を満たさない利用者はまず警告を受け、**20 操作**または5分の利用のいずれか早い方でアクセスが遮断される」と規定する。同ページは Entra 認証の既定適用、1,500超のコネクタ、条件付きアクセス・DLP・高度なコネクタポリシー・共有制限の自動適用も挙げる。

⚠️ 一次が片方の経路しか書いていない。 Learn 側は表題からして「Apps overview for admins (**Frontier**)」で、テナントの Frontier 登録を前提とする Cowork 経路しか記述していない。ブログが「既定で有効・推奨」と書く Copilot Studio 経路の Learn ページは本日時点で存在せず、Copilot Studio What's New 本文の `App Builder` は0件、Release Notes 全文の `app building` も0件である。MC1469329 が Copilot Studio 版を「次の数週間で」としており、2経路のうち後から来る側だけが先に文書化された形になっている。
