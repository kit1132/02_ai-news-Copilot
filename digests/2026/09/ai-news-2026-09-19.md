### 1. Cowork のローカルブラウザーに必要な Edge は 150 系から 152 系へ上がった — 8/29 に掲載した前提条件が置き換わった

**要点**: 必要 Edge バージョンが **150.0.4078.83** から **152.0.4191.53** へ引き上げられた。8/29 に前者を掲載して以来この数値に触れておらず、150 系・151 系のまま配ったテナントは文書上の最低要件を下回る。

**詳細**: `cowork/cowork-local-browser` の `ms.date` が **2026-08-27 → 2026-09-16**、`updated_at` が 2026-08-28T05:15Z → **2026-09-16T17:36Z** へ動いた。表記も「Edge 150 Stable 2 以上」から「recommended minimum Edge version 152.0.4191.53 or higher」へ変わっている。グループ単位の制御に必要な Edge 152（8/24 の週リリース）の記述は据え置きで、要件バージョンと制御バージョンが **152** に揃った形になる。管理者側の前提は変わらず、`Copilot > Settings > View All > Cowork settings` の **Allow browser access** が既定で無効のままである。

改訂では利用者から見た失敗時の挙動が4節ぶん増えた。

- 対応面の表: Cowork on the web（Edge）のみ対応、他ブラウザーは未対応、デスクトップアプリは「ブラウザー作業は Web 版で動く」と返す。モバイルも対象外
- Edge が無い場合: ブラウザーを使わない工程は最後まで実行し、**どの工程に Edge が要るか**を会話で名指しして `Get Microsoft Edge` のリンクを出す
- 組織がブロックするサイト: Purview DLP・条件付きアクセス・Web フィルタリング・ブラウザー管理ポリシーをそのまま継承し、止まった場合はブロックされた工程と手作業の代替手順を提示する
- 中断したタスク: タブを閉じる・スリープ・切断で**失敗させずに一時停止**し、同じ会話で「continue」「resume」等を送ると Edge の可用性を確かめて再開するか確認を求める

⚠️ 本文は対応面を **`m365.cloud.microsoft`** と書いており、8/18 に業務用 Copilot の既定入口が `copilot.cloud.microsoft` へ移った件（8/15 掲載）とは表記が揃っていない。

### 2. Cowork プラグインは Claude Code / Cursor のプラグインを CLI で取り込める — 配布物を作り直さずに M365 側へ持ち込む経路ができていた

**要点**: 掲載歴ゼロのプラグイン開発ページを検知した。`atk import openplugin` が既存プラグインを M365 マニフェストへ変換し、`SKILL.md` は**無変換でそのまま通る**。スキルの移植コストが「書き直し」から「マニフェスト補完」へ下がる。

**詳細**: `cowork/cowork-plugin-development`（`ms.date` **2026-09-17**・`updated_at` **2026-09-18T02:41Z**）は、Cowork 追跡集合の外にあった22ページのうちの1本で、全 digest を grep して掲載歴ゼロを確認した。⚠️ **本日の変更ではなく初検知**であり、この取り込み経路がいつ提供開始されたかは一次から確定できない（B-064 の対象がまた1本増えた形になる）。移行に要する時間は、取り込みが約5分、ゼロから作る場合が約30分と書かれている。

取り込みは Microsoft 365 Agents Toolkit CLI（`@microsoft/m365agentstoolkit-cli` の **1.1.12 以上**・Windows / macOS / Linux）で行う。

- 変換される成果物: `.claude-plugin/plugin.json`（または `.cursor-plugin/plugin.json`・`.plugin/plugin.json`）が `manifest.json` へ、`skills/*/SKILL.md` が `agentSkills[]` へ**書式そのままコピー**、`.mcp.json` が `agentConnectors[]` へ（URL と認証種別は自動判定）
- 変換されないもの: `commands/`（スラッシュコマンド）・`agents/`（サブエージェント）・`hooks/`（イベントハンドラ）は**いずれも未対応**
- 必須の追加入力: `--privacy-url` と `--terms-url`。元のプラグインマニフェストに対応フィールドが無く、M365 マニフェストは両方を必須とする
- ⚠️ 公開前の手作業: コネクタの `authorization.referenceId` は名前から導出された**プレースホルダー**で入るため、実際の OAuth クライアント登録 ID へ差し替える必要がある

運用面では次の制約が効く。

- スキルの読み込みは3層で、frontmatter が常時（約100トークン）、`SKILL.md` 本体が発火時（**5,000トークン未満**推奨）、`references/` が要求時（上限なし）
- 付随ファイルはスキルあたり **20個**・1個 **5MB**・合計 **10MB**・ダウンロード15秒まで。相対パスのみで `..` や隠しファイルは不可
- コネクタ要件は Streamable HTTP（HTTPS・TLS 1.2 以上）・JSON-RPC 2.0・`tools/list` と `tools/call`・1呼び出し **30秒未満**で、ストア公開品は稼働率 **99.9%** が推奨値
- サーバー側で Cowork からの要求を見分ける手段は2つあり、`User-Agent` は全要求に、`clientInfo` は `initialize` にのみ載る。⚠️ `copilot-cowork` を**大文字小文字無視の前方一致**で判定すること（`copilot-cowork/1.0` の完全一致はバージョン更新で壊れる）
- ⚠️ カスタムプラグインは**モバイルの Cowork では動かない**

公開はテナント内配布と、Partner Center 経由の Microsoft 365 App Store への一般公開の2段階である。

- https://learn.microsoft.com/en-us/microsoft-365/copilot/cowork/cowork-plugin-development
