## 今日のハイライト

### 1. [仕様] Copilot Studio のコストを M365 管理センターで管理するには AI 管理者ロールが要る — PPAC の管理者ロールは引き継がれず、MAC のポリシーが PPAC の設定より優先される

**要点**: TC の Copilot Studio ブログ（11/24）によると、管理者は M365 管理センターで、エージェント単位・環境単位のスペンディングポリシーを Copilot Studio に掛けられる（パブリックプレビュー）。ポリシーの上限は前払いと従量課金の両方に効く。PPAC の割り当てだけで上限を管理する前提は、MAC のポリシーを作った環境では成り立たない。

**詳細**: MC1530368 は 11/20 GA と書き、Roadmap 577834 は `In development` のままで、本記事の「パブリックプレビュー」と一致しない。
- ロール: Power Platform / Dynamics 365 の管理者は、ポリシーの設定に AI 管理者ロールが要る。自動では付与されない。環境管理者が使用量を見るには AI 閲覧者ロールが要る
- 優先順位: 対象の使用量では MAC が PPAC より優先される。エージェントのリソース／環境ポリシーが ID ポリシーより先に効き、2つの予算は合算されない
- ID 単位のポリシー: ユーザー・グループ単位の予算は「近日提供」のまま
- 移行: ポリシーを作って環境をリンクするまで何も変わらない。環境単位の割り当て、エージェントの上限、Draw from tenant credit pool のルールは PPAC に残る
- 予定: 2027年初めに、使用量に基づく推奨上限・推奨ロール・コードによるロール設定を出す計画
- https://techcommunity.microsoft.com/t5/copilot-studio-blog/how-to-manage-costs-for-copilot-studio-agents/ba-p/4576413

### 2. [破壊的変更] SPFx パッケージを app-only で自動配布する仕組みは 2027-01-31 までに権限の追加が要る — `Sites.ReadWrite.All` だけではテナント App Catalog に書き込めなくなる

**要点**: M365 Developer Blog（11/25）によると、2027-01-31 以降、app-only 認証でテナント App Catalog にパッケージを追加・更新する処理は、Office 365 SharePoint Online の `SharePointTenantSettings.ReadWrite.All` が無いと拒否されうる。11/25 に載せた Copilot UX コンポーネントを CI/CD で配る場合も、この権限チェックが掛かる。

**詳細**: 同じ名前の Microsoft Graph 側の権限では代わりにならず、SharePoint のアクセストークンに入っている必要がある。
- 対象の操作: Apps for SharePoint へのパッケージの追加・更新と、Tenant-Wide Extensions の追加・更新。テナント全体の拡張を登録しないパッケージでも、アップロード時に確認される
- 対象外: 管理者の UI 操作、委任認証の PnP PowerShell、読み取りと削除、展開済みの SPFx ソリューションの実行
- 手順: Entra のアプリ登録に権限を付け、テナント管理者の同意を得てトークンを取り直し、アップロード・更新を再テストする。既存のサイト権限は外さない
- https://devblogs.microsoft.com/microsoft365dev/action-required-update-app-only-permissions-for-sharepoint-tenant-app-catalog-writes/
