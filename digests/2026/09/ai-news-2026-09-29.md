## 今日のハイライト

### 1. [破壊的変更+新機能] Copilot Studio の既存エージェントは、Microsoft による Entra Agent ID への自動移行が始まった — 「作り直さないと付かない」前提が崩れた

**要点**: 旧来のアプリ登録で動く既存エージェントについて、Copilot Studio の一次が「Microsoft が自動移行を進めている」と書き換えた。移行はその場で変換され、client ID は変わらない。8/21 に掲載した「作り直して旧版を廃止する以外に経路はない」という前提は、Copilot Studio 側では成り立たなくなった。

**詳細**: 一次は Learn `govern-migrate-api-entra-agent-identity`（`ms.date` **2026-08-24 → 2026-09-24**・`updated_at` 2026-09-28T19:03Z・`git_commit_id` **5b67a171**）である。

- 自動移行: 本文は「Existing agents that use an app-registration identity are being automatically migrated by Microsoft」と現在進行形で書く。同じ docset の `admin-use-entra-agent-identities`（`ms.date` 2026-08-21）は「will be migrated by Microsoft in a future update」と未来形のままである
- 移行方式: アプリ登録の ID をその場で変換し、application (client) ID を維持する。チャネル登録やコネクタのように client ID を参照する設定は、同じ識別子のまま解決される
- 手動の先行移行（preview）: PPAC の Actions > Recommendations にある Advisor 推奨「Migrate Copilot Studio agents to Microsoft Entra Agent ID…」から、1件ずつでもバッチでも移行できる。検証に通らなければ旧 ID へ戻せる。実行できるのは Power Platform 管理者・Dynamics 365 管理者・グローバル管理者で、テナントの Power Platform インベントリが有効になっている必要がある
- 移行後の注意: テストでは動くエージェントでも、条件付きアクセスが認証を止めると **Teams でだけ応答しなくなる**場合があると明記されている
- ⚠️ 一次どうしの食い違い: Entra 側の `entra/agent-id/migrate-copilot-studio-agents-to-agent-id`（`ms.date` 2026-06-15）は「自動移行も in-place 移行もない」「作り直して旧版を廃止する」のままである。新規エージェントへの自動付与の開始日も、Entra 側は 3/18、Copilot Studio 側は May 2026 と食い違っている

- https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-use-entra-agent-identities
