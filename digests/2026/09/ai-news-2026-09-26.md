## 今日のハイライト

### 1. [料金+新機能] Copilot の課金が「利用上限付きの定額 USL」と「Copilot Credits の従量」に分かれた — 定額は無制限ではなくなり、Code と Managed Runtime は今日から従量の管理対象になる

**要点**: Microsoft は、日常業務の AI をユーザー単位の定額（USL）、Cowork・Code・Autopilot などの委任型の作業を従量（UBB）と整理し直した。USL には利用上限（fair use）が設けられ、Opus 5 のような新モデルは「上限付きで含む」扱いになる。M365 Copilot の定額は「どれだけ使っても同額」から「上限を超えたら Auto に切り替えるか従量へ移る」に変わった。

**詳細**: Tech Community の Microsoft Copilot Blog が **9/25 13:16Z**「Evolution of the Copilot pricing model」（記事ID 4559416）で告知した。

- USL の範囲: Chat と Word / Excel / PowerPoint などの日常作業。モデル選択も USL に含まれ、GPT-5.6 と Sonnet 5 は込み、Opus 5 などの新モデルは上限付きで含む
- 上限に達したとき: まず警告が出て、利用者は Auto へ切り替える（追加費用なし）か Copilot Credits へ移るかを選ぶ。記事は「大多数の人は上限に達しない」と書くが、上限の数値は示していない
- UBB の範囲: Cowork / Code / Autopilot、SharePoint の新しい高度な機能、Fable と Astra などのフロンティアモデル。UBB を使うには USL が前提になる。エンタープライズ顧客では、管理者がスペンディングポリシーを作るまで UBB は無効で課金もされない
- 本日から展開する FinOps 機能: コスト管理の対象に Code と Managed Runtime が加わり（Copilot Studio エージェントは10月予定）、グループ単位のモデルファミリー制御（Cowork から）、Cowork の消費インサイト、Graph API によるスペンディングポリシー管理、利用者本人のクレジット残高表示が入る

⚠️ Learn の `usage-based-billing-overview-copilot-credits`（`ms.date` **2026-09-25**・`updated_at` 9/25 17:34Z）は、対象サービスを Cowork・Cowork のアプリ・Work IQ API の3つと書いたままで、Code と Managed Runtime を載せていない。同ページによると、スペンディングポリシーの Auto-apply new services は既定で有効である（9/16 既報）。

- https://learn.microsoft.com/en-us/microsoft-365/copilot/usage-based-billing-overview-copilot-credits

### 2. [予定] 新しい Copilot（Home / Code / Autopilot）が Frontier で展開を始める — Chat と Cowork が1つの入口にまとまり、常駐エージェントが加わる

**要点**: Microsoft は Copilot を Home / Code / Autopilot の3つで組み直すと発表した。Home と Code は数週間以内に Frontier で展開を始め、Autopilot は9月末に Private Preview を広げる。M365 Copilot の入口が「Chat と Cowork を行き来する」形から「Home に集約される」形へ変わる。

**詳細**: 公式ブログ（blogs.microsoft.com・9/25 12:07Z「Introducing the new Copilot with Home, Code and Autopilot」）はゲートウェイ拒否のため本文を読めていない。本文の一次として、Partner Center 9月ページの 9/25 付項目（`updated_at` 2026-09-25T17:09Z・`git_commit_id` `630e11db`）を採った。

- Home: Chat と Cowork を1か所にまとめ、Word / Excel / PowerPoint を Copilot の中で使える（Office in Copilot）
- Code: 知識労働者が自然言語でアプリ・トラッカー・ダッシュボードを作る。二次報道によると GitHub Copilot と同じ基盤技術で動く
- Autopilot: クラウドで動き続ける常駐型の個人エージェント。二次報道は、独自の ID とメモリを持つこと、旧称が Scout であることを伝えている
- 展開: Frontier プログラム経由。Frontier は M365 管理センターの Copilot > Settings > Copilot Frontier で有効にし、既定は No access である
- パートナー向け: 10/13 に Partner Digital Airlift が開かれる

- https://learn.microsoft.com/en-us/partner-center/announcements/2026-september
- https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/

### 3. [新機能] Copilot Managed Runtime が Public Preview になり、Copilot Studio からのアプリ作成は既定で有効になる — アプリの実行基盤が M365 テナント内に入る

**要点**: Cowork・Copilot Code・Copilot Studio で作ったアプリを動かす実行基盤が、Copilot Managed Runtime の名前で Public Preview になった。SDK と CLI を使えば他社ツールで作ったアプリも載せられる。アプリは「作成ツールごとに別々に統制するもの」から「M365 管理センターで一括統制するもの」に変わった。

**詳細**: Microsoft Copilot Blog（Copilot Studio カテゴリ）が **9/25**「Build where you want, run with confidence」で告知した。管理者向けの Learn ページ `microsoft-365/admin/manage/apps/` の題名は "Copilot Managed Runtime overview and key concepts for admins (preview)" に変わり（`ms.date` **2026-09-25**）、`microsoft-365/managed-apps/` 配下に SDK と利用者向けのページが新設された。

- 作成経路の既定値: Copilot Studio は On（M365 管理センターで管理）、CLI は Off（環境設定と環境グループ規則で有効化）、Cowork は Frontier 参加テナントでのみ On
- 既定で無効な制御: Allow public GitHub repository と External artifacts（Microsoft 管理ビルド外の成果物のデプロイ）
- 課金: ビルドは作成した製品側で課金される。Copilot Studio は PPAC の環境単位、Cowork は作成者のスペンディングポリシーで課金される。⚠️ 実行時の課金は M365 管理センターで利用者単位に設定し、Copilot Studio エージェントの環境単位の課金モデルは使わない。Power Apps Premium の利用者は、API 要求上限の範囲内なら実行でクレジットを消費しない
- 統制: Entra 認証、条件付きアクセス、DLP、高度なコネクタポリシー、共有制限がアプリ作成時点から自動で掛かる。棚卸しは M365 管理センターの Apps > All apps で行う

- https://www.microsoft.com/en-us/copilot/blog/copilot-studio/build-where-you-want-run-with-confidence-now-microsoft-hosts-and-manages-the-code-created-by-copilot/
- https://learn.microsoft.com/en-us/microsoft-365/admin/manage/apps/
