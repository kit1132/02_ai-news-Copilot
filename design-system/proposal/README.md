取引先のお客様に提出する提案資料・調査報告のための体系です。読み手にとっての読みやすさと伝わりやすさを、見た目より優先します。暖かい紙色の地に、落ち着いた黒の文字と青1色のアクセントを置き、色の多い装飾は小さな丸印だけに抑えます。

## 文章の書き方

- です・ます調で書く。報告書・提案書の言い回しを使い、口語・比喩・誇張（「話すだけで」「劇的に」「AI の同僚」など）は使わない。
- 冒頭に資料の位置づけを書く（Notice）。例：「本資料は、Microsoft 社が公開している情報をもとに、個人で調査・整理した参考資料です。」
- 構成は「調査概要 → 要旨 → 詳細 → 検討事項 → 留意事項 → 出典」を基本にする。結論を先に書く。
- 1項目は1〜2文、1文60字以内を目安にする。
- 専門用語は初出で括弧書きの説明を付ける。例：「Frontier（管理者が有効化する先行提供の仕組み）」。
- 変更点は「これまで／これから」に加え、「できなくなること・変わること」を必ず書く。該当がなければ「公開情報上、廃止される機能の記載はありません」と明記する。
- 事実と予定を書き分ける：「提供開始」「〜予定（発表時点）」「未確認」。
- 日付は「2026年10月13日」の形式、数字・英字は半角。製品名は公式表記のまま書く。
- 絵文字、感嘆符、疑問形の見出しは使わない。
- 出典は末尾に番号付きで並べ、発行元・言語・日付を括弧で添える。

## 色

- ページの地は `canvas-soft`、カード・表・注記の面は `surface`。面は `hairline` の罫線で区切り、影は原則使わない（浮かせるときだけ `shadow-1`）。
- 文字は見出し・本文に `ink`、補足に `ink-secondary`、キャプション・出典に `ink-muted`。`ink-faint` は本文・注記・出典に使わない。
- 構造上のアクセントは `primary` の1色だけにする。リンク、強調ラベル、比較の「これから」側に使い、リンク文字は `surface` の上に置く。
- `secondary`（深い藍色）は表紙帯（TitleBand）だけに、資料1つにつき1回使う。
- `accent-*` は装飾専用（カテゴリの丸印など）。面の塗り、ボタン、文字には使わない。
- 比較と注記には提案資料向けの追加色を使う：「これから」は `tint-blue`、「できなくなること・注意」は `tint-orange` と `caution-ink`、「管理者への影響」は `admin-ink`。
- 色だけで意味を伝えない。状態には必ず文字ラベルを付ける。
- フォーカス表示は `primary` の2px実線（どの面でも3:1以上）。

## 文字

- 書体は Google Fonts の Inter（英数字）と Noto Sans JP（日本語）を使う。ファミリー `sans` の順で指定し、読み込みは `https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700&family=Noto+Sans+JP:wght@400;600;700&display=swap`。スライドや文書ソフトで編集する場合も同じ2書体を使う。
- 日本語には負の字間を使わない。本文は `body`（16px、行間1.85、字間0.04em）、カードや表の中は `body-sm`、キャプションは `caption`、ラベルは `eyebrow`。
- 見出しは `display`（表紙）、`heading-1`（章）、`heading-2`（節・カード名）、`title`（小見出し）。太さは見出し700、ラベル600、本文400。
- 本文の1行は35〜40字を目安にし、本文の段落幅を約46rem以内に収める。強調は語句単位で最小限にする。

## 余白とレイアウト

- 余白は `space-*` から選ぶ：カードの内側 `space-lg`、カード同士 `space-xl`、節の間 `space-xxl`、章の間 `space-section`。
- 罫線より余白でまとまりを作る。罫線は章見出しの下と表の行の区切りにだけ引く。
- 1段組みを基本にし、カードは2〜3列で高さをそろえる。幅600px以下では1列にする。
- 角丸は注記・表・比較パネルに `radius-md`、カード・図版に `radius-lg`、表紙帯に `radius-xl`、バッジと丸印に `radius-full`。

## 図版

- 画面の画像は公式の出典から引用し、キャプションに出典と画面の種類（例：「Microsoft Edge の新しいタブ ページの画面」）を書く。
- 図版は `hairline` の罫線で囲み、トリミングや加工はしない。
- 説明する項目の中に置き、関係のない画像を飾りとして置かない。

## アイコン

- 専用のアイコンセットはありません。意味は文字ラベルで伝え、補助に `pd-dot` の丸印を使う。
- 絵文字は使わない。

## コンポーネント

- 文書全体を `pd-doc` で包む（地色・書体・行間・字間が入る）。クラスは `components/bundle.css` の `pd-` で始まるものを使う。
- 資料の流れ：TitleBand（表紙帯）→ Notice（前提・免責）→ Card（要旨）→ Comparison（変更点）→ DataTable（予定・料金）→ Notice（留意事項）。
- 各コンポーネントの使い方はそれぞれの README に従う。
