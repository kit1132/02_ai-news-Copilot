### 1. Copilot Studio の課金開始点が「公開後」から「作り始めた瞬間」へ動いた — GitHub Copilot ハーネスは従量課金

**要点**: GitHub Copilot ハーネスで作るエージェントとワークフローが、Copilot Credits の従量課金に切り替わった。標準ハーネスの「公開してから課金」を前提に PoC を回してきた見積もりは、作成・テスト段階から課金される前提へ引き直すことになる。

**詳細**: Copilot Studio のドキュメントが *harness*（ランタイム層）を軸に再編された。ハーネスは設計物とモデルの間に位置し、いつモデルを呼ぶか・何を送るか・返答をどう解釈してどのツールを呼ぶかを決める。3種類が定義されている。

- GitHub Copilot ハーネス: 推論重視の多段階業務向け。Word / Excel / PowerPoint / PDF をネイティブに作成・編集し、Skills と Memory に対応、各タスクをサンドボックスで実行する。課金は Copilot Credits
- 標準ハーネス: ルールベースのエージェントとエージェントフロー向け。従来どおりライセンス・課金は `billing-licensing` の体系
- Copilot チャットハーネス: M365 Copilot Chat の拡張向け。消費ベース、または M365 Copilot ユーザーサブスクリプションライセンスに含まれる

従量課金の中身は次のとおり。

- 課金対象は LLM トークン・ツール（ナレッジと MCP を含む）・ハーネス自体の3つで、いずれかを使う体験はすべてクレジットを消費する
- 標準ハーネスが publish 後に課金を始めるのに対し、GitHub Copilot ハーネスは**構築を始めた時点から**課金する。自然言語でのソリューション作成、エージェントのプレビューとテスト、評価の生成と作成がいずれも消費対象
- クレジットが尽きると、エンドユーザー側はエージェントが応答を停止し、メーカー側は自然言語オーサリング・プレビュー/テスト・評価生成ができなくなる。業務停止を避けるため一定のオーバレージは猶予される
- 調達は Azure サブスクリプション経由の従量課金メーターと、1年前払いの事前購入プラン（CCCU プール）の2通り。配分と監視は Power Platform 管理センター、エージェント単位の消費は Monitor ページで確認する

### 2. ハーネスの選択は後から変えられない — 共有相手に編集させるにはハーネスをオフにするしかない

**要点**: エージェントは作成時に選んだハーネスから移行できず、GitHub Copilot ハーネスのエージェントは共有しても閲覧とテストまでしか許可できない。「後で乗り換える」「共同で編集する」を前提にした進め方が、作成前に決め切る前提へ変わる。

**詳細**: 制約は次の4点で、いずれも一次ページに明記されている。

- GitHub Copilot ハーネスで作ったエージェントは標準ハーネスへ移せず、逆方向も同様に移せない。どちらを使うかは新規作成時に選ぶ
- 共有パネルで付与できるのは閲覧権限だけで、編集権限は渡せない。編集を許可するには Copilot Studio のホーム画面で「Use GitHub Copilot harness」をオフにする必要がある
- 共有先は Copilot Studio のユーザー単位ライセンス保有者に限られ、対象エージェントのユーザー認証が **Authenticate with Microsoft** に設定されていることが前提になる
- 詳細を見せずに実行だけさせたい場合は、Organization & data の End user access を「Everyone in your organization」に切り替える。この場合、相手はエージェントを探して使えるが詳細の閲覧も編集もできない

自然言語での作成体験は Anthropic モデルを使うため、Anthropic モデルへのアクセスが有効な環境でしか利用できない点も併記されている。
