変更前の課題と変更後の対応を1行ずつ対にして並べ、行ごとに判定を付ける比較ブロックです。その下に「できなくなること」と「管理者への影響」を置きます。

- `pd-pairs` の1行に、左 `pd-pairs__before`（`canvas-soft`）の「これまでの課題」、矢印 `pd-pairs__arrow`、右 `pd-pairs__after`（`tint-blue`）の「これからの対応」、右端 `pd-pairs__verdict` の判定バッジを置く。左の課題1つに対し、右にはその課題への対応だけを書く。
- 1行目に見出し行（`pd-pairs__head`、右の見出しは `pd-pairs__head--after`）を置く。幅600px以下では見出し行が消え、各セルの `pd-pairs__tag` が代わりに表示される。
- 判定は Badge を使い、文字で意味を伝える：対応済み（`pd-dot--green`）、対応予定（既定の丸印）、限定提供（`pd-dot--purple`）。比較の前に `pd-legend` で判定の意味を1回だけ示す。
- 課題は「〜する必要がある」「〜しにくい」、対応は「〜できる」「〜する」で終える。課題のない変更点は書かない（対にならない変更は別の段落で扱う）。
- 画面の画像は最後の行に置き、左に変更前、右に変更後を入れる。変更後の公式画像がない場合は、その旨を `pd-pairs__none` で明記し、変更前の画像を変更後の欄に置かない。
- 比較の下に `pd-note--loss`（`tint-orange`、ラベル `caution-ink`）で「できなくなること・変わること」を置く。該当がなければ「公開情報上、廃止される機能の記載はありません」と明記し、欄を省略しない。
- 最後に `pd-note--admin`（`surface`、ラベル `admin-ink`）で「管理者への影響」を置く。
- 課題と対応を対にできない自由記述の比較には、左右2枠の `pd-compare` を使う。
