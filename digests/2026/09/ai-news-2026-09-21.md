### 1. [破壊的変更+新機能] Grok が 9/18 から Microsoft のサブプロセッサ経路でも使えるようになった — 9/13 に掲載した「契約保護が外れる」前提が、新経路には当てはまらない

**要点**: SpaceXAI がサブプロセッサとして提供開始された。Grok は「Product Terms も DPA も著作権補償も適用されない外部 LLM」から「Microsoft の契約枠内に入るモデル」へ変わったが、⚠️ 旧設定は新経路へ引き継がれない。

**詳細**: 一次 `spacexai-subprocessor`（`ms.date` **2026-09-18**・`updated_at` 2026-09-18T15:54Z・`git_commit_id` `051f9c45`）が本日初検知され、全 digest で掲載歴ゼロだった。ページは2つの日付を明記する——SpaceXAI が Microsoft Online Services Subprocessors List に加わったのが **2026-09-10**、対象顧客が実際に使えるようになったのが **2026-09-18** である。

- 適用される保護: Microsoft Product Terms、Data Protection Addendum（DPA）、Enterprise Data Protection、そして Word / Excel / PowerPoint の Copilot については **Customer Copyright Commitment**
- 提供範囲: Microsoft Frontier プログラム加入テナントのみ。提供開始時点でモデルセレクター経由の **Word / Excel / PowerPoint** に限られる
- 対象外: EU・EFTA・英国、政府クラウド（GCC / GCC High / DoD）、その他のソブリンクラウド。Frontier 加入済みでも対象外である
- 除外事項: SpaceXAI 側の認証は SpaceXAI が管理し、**FedRAMP High 認可は受けていない**。在国内処理（in-country processing）のコミットメントからも除外される
- Copilot Studio 側: SpaceXAI は従来どおり**独立プロセッサ**として提供され続ける。ハーネスのモデル表にある Grok 4.1 Fast の位置づけは変わらない

⚠️ **管理者が踏む必要のある手順が1つ増えている。** 新しいサブプロセッサ設定（M365 管理センター > Copilot > Settings > View all > **AI providers operating as Microsoft subprocessors** > SpaceXAI）は、9/13 に掲載した旧設定（同画面の `AI providers for other large language models`）とは**別の設定**である。ページは「旧設定でユーザーにアクセスを与えていた場合、新しいサブプロセッサ設定を有効にしてユーザー／グループを割り当て直す必要がある。以前の設定は自動的に引き継がれない」と明記する。既定は全対象顧客で無効で、操作には AI Administrator か Global Administrator が要る。

### 2. [新機能] 非連邦 GCC は 7/22 から Anthropic モデルを有効化できる — 政府クラウドでも「境界の外へ出す」選択肢が管理者に開いている

**要点**: 非連邦 GCC テナントは M365 管理センターの設定1つで Anthropic モデルを使えるが、有効化した瞬間に顧客データは FedRAMP 認可済みの米国政府クラウドの外で処理される。政府テナント＝境界内処理という前提は、管理者の操作1つで崩れる。

**詳細**: 一次 `anthropic-non-federal-gcc`（`ms.date` **2026-09-18**・`updated_at` 2026-09-18T19:08Z・`git_commit_id` `6c071bff`）が本日初検知された。設定そのものは **2026-07-22** から提供されており、⚠️ **本ダイジェストは2か月間これを掲載していなかった**。適用対象は GCC の非連邦顧客のみで、GCC の連邦顧客・GCC High・DoD には適用されない。

- 前提ライセンス: **Microsoft Copilot (Premium)**。モデルはドロップダウンのモデルピッカーに出るが、現時点で出るのは Microsoft Copilot アプリと Web の **Copilot Chat だけ**である
- 既定: 無効。有効化には AI Administrator か Global Administrator が要り、`AI providers operating as Microsoft subprocessors` で Anthropic を選び、条件への同意チェックを入れてから All users または個別ユーザー／グループを指定する。無効化は同じ画面で **No users** を選ぶ
- データ所在: 有効化すると顧客データは**商用環境で処理**される。ページ自身が「これは GCC が前提とするソブリン処理とは一致しない」と書いている
- 認可の範囲外: **FedRAMP Moderate** にも DoD SRG にも含まれず、CJIS・IRS 1075 等の既存のコンプライアンス証明にも入らない
- 使ってはいけない用途: CUI・機密・輸出管理対象・高機微の政府データの処理、および厳格な監査可能性や制御プレーン分離を要する業務
- 学習には使われない: プロンプトと応答は Anthropic の基盤モデルの学習には使われず、サービス提供と不正利用監視のためだけに処理される

⚠️ **連邦 GCC・GCC High・DoD では設定項目自体が現れない。** 親ページ `connect-to-ai-subprocessor` は、これらのクラウドとその他のソブリンクラウドでは Anthropic モデルの選択肢が M365 管理センターに表示されないと明記する。9/20 に掲載した Copilot Cowork の政府クラウド展開（Roadmap **571637**・GA November CY2026）と読み合わせると、政府クラウドでモデル選択が開くかどうかはクラウドの区分ごとに別々に決まっている。

- https://learn.microsoft.com/en-us/microsoft-365/copilot/connect-to-ai-subprocessor

### 3. [仕様] SharePoint リストのナレッジソースに上限値が明文化された — GA 期日まで9日の機能を、設計段階で測れるようになる

**要点**: Copilot Studio の SharePoint リスト連携に、行数・リスト数・推奨モデルの上限が一次で入った。「構造化データを繋げば答えられる」から「12万行・10リスト・GPT 5.4 以上が実用域」へ、見積もりの基準が具体的な数値に変わる。

**詳細**: 一次 `agents-experience/knowledge-sharepoint-lists`（`ms.date` **2026-09-15**・`updated_at` 2026-09-17T19:04Z・`git_commit_id` `96d24c67`）が本日初検知され、掲載歴はゼロだった。対象は GitHub Copilot ハーネス製のエージェントで、ヘルプデスクチケット・コースカタログ・バックログのような運用データに自然言語で答えさせる用途を想定する。Roadmap **566859**（GA 期日 **September CY2026**）に対応する機能で、期日まで **9日**である。

- 最大リストサイズ: **120,000行**まで。これより大きいリストも接続できるが品質とレイテンシが劣化する。全リスト合計で 12万行に収めるのが最良（例: 1.2万行×10リスト、3.5万行×3リスト）
- リスト数: 1エージェントあたり **10リスト**まで。追加は Build タブ > Knowledge > SharePoint から一度に10件まで選べる
- 推奨モデル: **GPT 5.4 以上**と Sonnet 系。他のモデルも動くが返る結果の品質は落ちる
- ⚠️ スロットリング: 10リスト×3.5万行の全体を走査させるような質問はスロットリングされるか高レイテンシになると明記されている
- 対応クエリ: 完全一致ではなく意味理解に基づく検索と FAQ、および構造化データに対する集計・分析クエリ（「チケットのクローズまでの平均リードタイム」「MacBook の調達依頼は何件か」等）
- 設計上の注意: エージェントはリスト項目の**タイトルを参照先選定のシグナルの1つ**として使う。汎用的なタイトルや空のタイトルは拾われにくくなり、この挙動に設定項目は無い

⚠️ **利用・構築・テスト・評価のいずれも Copilot Credits を消費する。** ページ冒頭の注記が従量課金の対象だと明示しており、12万行のリストを評価で繰り返し叩く設計はコストに直結する。
